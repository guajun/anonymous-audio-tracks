# 20 — 抽查记录：漏检 / 误检 / 跨轴能量代理（issue #33）

> **口径（冻结）**：真实音乐**没有**精确真值。本文件记录**抽查与迹象**（overlay 试听、能量比、
> 跨轴能量代理、独立检测器差异），**不是**总体准确率；own/other 能量比**不能**证明分离泄露。
> 抽查对象：真实 run `e2e-real-20261001-02` 的 result（110 个 onset，3 个 stem）。

## 0. 更正声明（supersede 旧量化值，R1 修订）

本文件**初版**曾发布一组 “isolation ≈0.95–1.0” 的“串音/隔离度”数字。经 review 复核，那组数字由
两个读取 bug 产生，**无效并作废**：

1. `common.read_mono` 没有使用 WAV fmt 的实际编码 tag，把 SAM 的 **IEEE float32** stem 字节按
   **int32** 解码（合成值 `[0,.25,-.5,1]` 被解成 `[0,.488,-.508,.496]`，已复现）；
2. `spotcheck.stats` 丢弃各 stem 自己的采样率，用 **44.1 kHz 的 mix** 采样率去索引 **48 kHz 的 stem**
   （时间窗错位约 8.8%）。

修复：读取器按实际 tag 解码（PCM 16/24/32 与 IEEE float 32/64，其它拒收）、逐 stem 用**自己的**
采样率按秒取窗；并在**未改动的**原始 result/stems 上离线重算（无新 API/GPU）。
旧数字（`own/other≈0.95–1.0`）**不得引用**；下述 §4 是替代值。同时把口径从“隔离度/串音率”改为
**跨轴能量代理（cross-stem energy proxy）**：它只是 own/other 能量比，不是测得的分离度——
多声源同时发声时比值≈1 并不能证明泄露，且未控制各 stem 增益差异。

另：Gemini 在本次 run 里 `audio_attach` 的**只有 mix clip**（2 次都是 `e2e-clip-001.wav`），
**没有**听过任何 target stem。因此它对 stem 内容/串音的描述是**推断/推测**（基于听 mix +
读 DSP 数字），不是“听过 stem 证实”；本文件按此标注。

## 4. 跨轴能量代理（修复后重算；**不是**分离度/串音率）

各 stem 用**自己的 48 kHz 时钟**按秒取窗（own=该事件所属 stem，other=其余 stem 平均）：

| onset（s） | 来源 | own RMS | other RMS | cross-stem energy ratio（代理） |
|---|---|---|---|---|
| 0.1973 | drums | 0.225 | 0.119 | 1.891 |
| 5.3973 | synthesizer | 0.224 | 0.112 | 1.994 |
| 10.5973 | drums | 0.208 | 0.207 | 1.004 |
| 13.2747 | bass | 0.203 | 0.165 | 1.230 |
| 15.9200 | bass | 0.119 | 0.186 | 0.639 |

**能说与不能说**：可以说“在 3/5 抽查点，own stem 能量高于其它 stem（1.2–2.0×）”；
**不能**说“测得串音率 X%”或“分离泄露被证实/证伪”——多声源同时发声时比值会自然趋近 1
（如 10.5973 s 的 1.004），且未控制 stem 增益。Gemini 对 stem 内容的描述（§5）是**推断**。
