# 提示词迭代记录

目标分成两步：SAM 提取同一来源；Gemini 定位来源的起音。两者分别评价，不能将音色描述漂亮或 confidence 高当作正确依据。

已确认：用户认为 SAM 的 `melodic sound` + 原曲11.18–11.50秒 anchor 提取很接近目标。保留该组合为基线；这不是每个起音都正确的真值。

Gemini 基线：`runs/20260929-001042-747776/tracks.json`。20个onset；19个间隔中17个为1.5秒；20个activity区间均为0.5秒。待听觉验证，不能仅据此判错。

v2 假设：移除具体乐器、鼓数量比例与历史BPM等诱导，分开要求身份确认、时间定位和持续时间核查，可能减少模板化输出。该假设尚未经线上对照证实。

文件：
- `prompt-general-v2.txt`：不含歌曲特定信息的规则模板。
- `target-breeze.json`：单独保存本次目标参考、用户确认的SAM提示和确认范围。
- `build_prompt.py`：合成 `prompt-breeze-v2.txt`；不调用API。
- `audit_tracks.py`：统计输出模式；不判断听觉正确性。

运行这次对照：
```powershell
uv run --locked python build_prompt.py
uv run --locked python analyze.py --prompt prompt-breeze-v2.txt
uv run --locked python audit_tracks.py runs\新结果目录\tracks.json
```

现有调用器仍针对这次30秒片段；修改目标数据为别的歌曲/裁切范围时，还需要同步调用器的音频路径、上传标签和时长验证，不能只换case就认为完整支持任意音频。

建议的反馈闭环：
1. 固定原始音频、参考片段和SAM成功基线，保留每版提示与输出。
2. 先试听抽查 3～5 个明确出现点和几个明确不属于目标的片段。可以仅写时间附近，不要求一次标完整首歌。
3. 分别记漏检、误检、错认声音和时间偏差；不要只比较输出数量或模型自评置信度。
4. 从一条可复现的问题提出一条通用修改。对同音频重复调用以估计随机波动，再测试另一段或另一首，防止只适配Breeze。
5. 对时间定位能力做裁切一致性检查：同一真实事件在原片段和偏移裁切中，换回原时间后应接近。不要把大量相邻短切片一致性当独立准确率。
6. 如果只改提示一直无法改善时间定位，保留Gemini/SAM的目标识别作用，另用音频起音检测产生候选并人工核对，不继续堆禁令或让模型用文字自评充当真值。

下一步可以将已认可的SAM目标作为额外听觉参考，但应单独作为一个实验条件，不能与提示词改动同时混在一起；机器分离音频的漏音/伪影可能传递给Gemini。
